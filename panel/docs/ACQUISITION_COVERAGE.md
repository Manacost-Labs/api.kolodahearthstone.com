# Покрытие источников в панели

Раздел `/?action=analytics&stats=acquisition#statistics` находится рядом с
«Обзором». Он использует существующую GitHub-авторизацию и GET-only мост
`analytics.php?module=acquisition`. Публичный API не меняется.

Таблица содержит весь реестр из существующего локального `/demo/overview`.
Поиск работает по ID, сайту и описанию; фильтр состояния сохраняется в URL
как `stats_coverage`. Сначала идут частичные и старые снимки. В «Подробнее»
доступны снимок, патч, область/параметры страницы, подтверждение конца списка
и фильтров, состояния подробностей и стоимость попыток, если она известна.

`Найдено / ожидается` показывает `?`, если исходное число неизвестно.
`Подробности / найдено` считает только успешно полученные подробности;
подтверждённое отсутствие видно отдельно в деталях и не считается ошибкой.
«Не завершено» включает pending, running, retry, failed и not_requested.
Полный снимок не доказывает свежесть, публикацию, все поля или другие срезы.
Статус running означает «было в работе при наблюдении», а не живого работника.
Снимки старше 24 часов отмечаются отдельно и исключаются из числа полных
свежих наблюдений в сводке; это порог давности отчёта, не SLO источника.

## Передача наблюдений из Python

Используйте существующие [отчёты покрытия](../../docs/ACQUISITION_COVERAGE.md).
Например, после разрешённого сбора BG и подтверждения listing evidence:

```python
from app.acquisition_panel import build_panel_snapshot
from app.bg_detail_acquisition import bg_detail_report

bg = bg_detail_report(queue, view, listing_rows, listing=verified_listing)
observation = {**bg, "observed_at": actual_observation_time_utc}
snapshot = build_panel_snapshot([observation])
```

`queue`, `view`, `listing_rows` и `verified_listing` предоставляются реальным
адаптером. Пример сам ничего не скачивает. `observed_at` — время измерения
состояния; при повторном экспорте старого наблюдения его нельзя заменять на now.
Для других источников передайте `{coverage: coverage_report(...), observed_at: ...}`.
`credits_spent` и `unknown_cost_attempts` необязательны: неизвестное остаётся null.

Экспорт принимает JSON-массив таких наблюдений, по одному на источник:

```sh
.venv/bin/python scripts/export_acquisition_panel.py \
  --observations /explicit/private/observations.json \
  --output /explicit/private/acquisition-panel.json
```

Без `--observations` формируется реестр со всеми статусами unknown. Для
повторного экспорта в тот же файл требуется явный `--replace`. Ошибка входных
данных не уничтожает предыдущий отчёт. Файл создаётся атомарно с правами 0600;
экспорт не открывает очередь, рабочую БД и не обращается в сеть. Временный файл
находится в том же каталоге. JSON и файл ограничены 1 MiB.

Экспортёр проверяет принадлежность source/snapshot/patch/URL scope реестру,
арифметику, типы, дубли и время. Лишние поля, включая rows и raw payload,
отбрасываются. Эти проверки не заменяют проверку страницы доверенным адаптером.

## Настройка чтения и границы безопасности

Администратор окружения задаёт `HS_ACQUISITION_PANEL_REPORT` как абсолютный путь
к этому JSON вне web-root. Каталог не должен быть доступен на запись другим
пользователям. Символическая ссылка вместо файла не поддерживается. При
разделённых пользователях экспортёра и PHP нужно отдельно согласовать группу
и права чтения, сохраняя приватность; exporter этого автоматически не делает.

Путь нельзя передать из браузера. PHP читает только ограниченный JSON; он не
запускает Python/команды и не открывает SQLite. Доступ к очереди и её результатам
остаётся у Python-адаптера. Все строки выводятся через безопасный текстовый DOM.
Если файл не настроен, недоступен или противоречив, реестр остаётся виден со
статусами «Не проверено» и предупреждением. Ошибки не раскрывают путь или тело
файла. Время сборки отчёта показывается отдельно от времени наблюдения строки.

Открытие/обновление раздела не запускает сбор или повторы. Кэш существующего
реестра не является кэшем наблюдений: файл перечитывается при каждом запросе
этого модуля. При изменении состава реестра отсутствующие источники остаются
unknown, а несовпадение состава явно отмечается.

## Проверка, включение и откат

```sh
.venv/bin/python -m pytest -q tests/test_acquisition_panel.py
.venv/bin/python -m unittest discover -s panel/tests -p test_acquisition_panel_bridge.py
php panel/tests/acquisition_test.php
make check
make security
```

`panel/tests/acquisition_panel_fixture.php` использует только синтетические
данные; варианты `mode=missing`, `invalid`, `error`, `loading`, `xss` предназначены
для локального браузерного теста. Это не тест рабочей авторизации или данных.
Перед выпуском нужны браузерная проверка узкого/широкого экрана, поиска, фильтра,
клавиатуры и drawer, затем согласованный приватный путь и включение экспорта.

Безопасный откат — убрать модуль из навигации/реестра и вернуть версию JS;
ни очередь, ни отчёты, ни datasets удалять не требуется. Снятие настройки файла
возвращает unknown-first отображение без изменения данных (покрыто тестами).

Автоматический экспорт из расписаний, адаптеры остальных семейств и сбор XHR
не включены этим модулем. Производители без наблюдений не выдаются за работающие.
