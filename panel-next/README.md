# HS Data Panel — Next.js

Новый интерфейс всей панели: каталоги, редактор карт, переводы Wiki, статистика, надёжность сбора, управление источниками и API-токены. Сохраняет выбранную светлую галерею, четыре темы и прежние параметры адресов.

## Границы миграции

Next.js / React / TypeScript обслуживают интерфейс и серверный relay `/api/panel`. Существующие PHP/FastAPI операции остаются владельцами данных, SQL, правил валидации, CSRF, лимитов, расписаний и одноразового выпуска токенов. Схемы БД не меняются.

`panel/next-data.php` экспортирует явный JSON-контракт версии 1. Реестр аналитики возвращает только названия и параметры. Сервер Next передаёт в фиксированный адаптер только cookie `koloda_admin`; credentials API, OAuth и DB остаются в PHP. Все ответы с данными закрыты сессией и используют `private, no-store`. POST дополнительно проверяет Origin и существующий CSRF. Секрет выпущенного токена хранится только в состоянии страницы.

Чистые модели свежести и классификации парсеров копируются при сборке из существующих проверенных JS-модулей; менять определения метрик независимо от backend не следует.

## Разработка и проверки

Требуется Node.js >=22.13. Установка: `npm ci`; полный gate: `npm run check`. Сборка не обращается к API за данными или внешними шрифтами. `make check` в корне включает этот gate.

HTTP-интеграционные тесты сами запускают standalone Next и локальный fixture на временных портах. Браузерные проверки используют отдельный Chromium, фиксированные тестовые порты и вымышленные данные; реальные токены и парсеры не запускаются.

Каталог сохраняет ввод и результаты при обновлении фильтров; явные переходы по страницам добавляются в историю, поиск и вид заменяют текущий адрес. Шапка находится в layout, а возвращение через её ссылку «Каталог» восстанавливает адрес и прокрутку. Предпочтение вида записывается в отдельную cookie `hs_catalog_view`; параметр `view` в адресе имеет приоритет.

Для проверки гонок и возврата в каталог включить задержку fixture: `PANEL_FIXTURE_DELAY_MS=650 node tests/fixture-server.mjs`. После запуска локальной панели выполнить `PANEL_TEST_ORIGIN=http://127.0.0.1:4180 node tests/catalog-browser.mjs`; нужен установленный `playwright-cli` или путь к его wrapper в `PLAYWRIGHT_CLI`. Проверка допускает только localhost, блокирует внешние изображения и проверяет поиск, быстрые фильтры, историю, три вида, возврат фокуса, прокрутку, ширины 320–1440 и reduced motion. Снимки сохраняются в `/tmp/koloda-panel-ux-browser` (или `PANEL_QA_OUTPUT`).

Для ручной локальной проверки:

```sh
node tests/fixture-server.mjs
# В другом терминале:
PANEL_BACKEND_ORIGIN=http://127.0.0.1:18768 PANEL_PUBLIC_ORIGIN=http://127.0.0.1:4180 npm start
```

Для браузерного regression набора запустить отдельный Chromium с CDP на `127.0.0.1:18766`, затем `node tests/browser.mjs`. Он устанавливает только тестовую сессию, блокирует внешние HTTPS-запросы и проверяет поиск, страницы, модальные окна/фокус, мобильные размеры, статистику, подтверждения и тестовые мутации. Скриншоты по умолчанию сохраняются в `/tmp/koloda-next-browser-qa`; путь задаётся `PANEL_QA_OUTPUT`.

`/` фокусирует поиск. Ctrl+K / Cmd+K открывают быстрый переход; Escape закрывает диалоги с восстановлением фокуса.

## Релиз и откат

Сборка создаёт `.next/standalone` вместе со static и локальными шрифтами. `scripts/deploy-panel-next.sh` размещает только этот артефакт в новом каталоге `/srv/api-kolodahearthstone/panel-next/releases/<release>`, переключает `current`, перезапускает `koloda-panel-next.service` и проверяет auth-redirect. Предыдущие релизы сохраняются. Скрипт вызывается оператором после разрешения на публикацию.

Nginx направляет только корень, `/api/panel` и `/_next/` в Node на `127.0.0.1:4181`. Отдельный PHP-адаптер слушает только `127.0.0.1:18769` и разрешает три конкретных entrypoint. Публичный `/next-data.php` закрыт. Маршруты REST, GraphQL, GitHub OAuth и media сохраняются. `/index.php` остаётся старым PHP-интерфейсом.

Порядок: полный gate; отдельный PHP-релиз с JSON-адаптером; standalone релиз; резервная копия Nginx; `nginx -t`; reload; проверка auth, API-401 и static. Не копировать `.env`, config.php, uploads, var или runtime-сессии в Next-артефакт. PHP-релиз должен сохранять production-only совместимость существующего API.

Откат: восстановить сохранённую конфигурацию Nginx, проверить её и reload. Это немедленно возвращает PHP-корень. При необходимости атомарно переключить Next `current` на предыдущий immutable релиз и restart сервиса. Не удалять releases, данные или backup.

## Проверенный этап

Перенесены все основные разделы. Типы, unit-тесты, HTTP-проверки и браузерные сценарии проходят. Проверки реальных административных мутаций production не выполняются: их контракт остаётся в существующем backend и покрыт его regression suite. Полный repository security baseline имеет существующие находки в других пакетах (orchestration и старый прототип); audit нового `panel-next` не показывает уязвимостей.
