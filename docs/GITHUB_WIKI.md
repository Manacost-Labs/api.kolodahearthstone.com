# Публикация GitHub Wiki

## Текущее состояние

Подготовленные страницы находятся в [`wiki/`](../wiki/). Они читаются прямо в
репозитории и одновременно соответствуют структуре GitHub Wiki:

- `Home.md` — главная;
- `_Sidebar.md` — постоянная навигация;
- `_Footer.md` — общий footer;
- отдельные страницы пользователя, API, архитектуры, эксплуатации и FAQ.

На момент подготовки GitHub API возвращает `has_wiki=false` для приватного
репозитория и отклоняет включение этой функции. Это ограничение настройки/плана
GitHub, а не отсутствие подготовленных файлов.

## Источник истины

Редактируйте `wiki/*.md` в основном репозитории и публикуйте их после merge.
Не вносите долговременные изменения только в отдельный `.wiki.git`: иначе
документация разойдётся с reviewed source.

## Как опубликовать

1. Сделайте GitHub Wiki доступной в **Settings → Features → Wikis**. Для
   приватного репозитория может потребоваться подходящий план организации.
2. Создайте начальную страницу **Home** в веб‑интерфейсе GitHub. После этого
   GitHub создаст отдельный Wiki Git repository.
3. Из актуального checkout запустите:

```bash
scripts/publish-github-wiki.sh
```

Скрипт:

- проверяет, что Wiki действительно включена;
- клонирует отдельный Wiki repository во временный каталог;
- заменяет только Markdown‑страницы подготовленным `wiki/` комплектом;
- преобразует repo-relative ссылки в URL GitHub Wiki и основного репозитория;
- показывает diff;
- создаёт commit и отправляет default branch Wiki.

## Проверка после публикации

Откройте:

```text
https://github.com/Manacost-Labs/api.kolodahearthstone.com/wiki
```

Проверьте:

- Home открывается по умолчанию;
- Sidebar присутствует на каждой странице;
- ссылки между страницами работают;
- code blocks и Mermaid diagram render;
- ссылки на `docs/`, `DEPLOY.md` и API ведут на нужные страницы;
- в истории Wiki виден commit публикации.

## Если публикация недоступна

Не делайте repository public только ради Wiki. Продолжайте использовать
[`wiki/Home.md`](../wiki/Home.md) как repo-native documentation hub. Когда
организация разрешит GitHub Wiki, подготовленный комплект можно опубликовать
без переписывания документации.
