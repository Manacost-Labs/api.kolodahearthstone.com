# Scrape providers

The shared protected-page stack uses this fixed order:

1. Scrape.do — primary renderer and paid subscription.
2. Firecrawl — rotating key pool.
3. Scrapfly — last-resort rotating key pool.

The policy lives in `app/firecrawl_backend.py` and is exposed through
`scrape_source()` and `scrape_source_with_options()`. The latter accepts
`skip_providers={"scrape_do", "firecrawl", "scrapfly"}` for callers that have
already attempted a provider intentionally.

Scrape.do target headers use `extraHeaders=true` and `Sd-*` header names by
default, preserving the browser headers generated by Scrape.do. Exact
`forwardHeaders=true` forwarding is opt-in. Temporary 429/5xx responses receive
one bounded retry; account failures immediately advance to Firecrawl. A 2xx
Cloudflare challenge may escalate from the standard profile to Super, then the
chain continues.

Configuration:

- `HS_SCRAPE_DO_TOKEN`, `HS_SCRAPE_DO_TIMEOUT_SECONDS`
- `HS_FIRECRAWL_API_KEYS`, `HS_FIRECRAWL_KEY_ROTATION_CREDITS`
- `HS_SCRAPFLY_API_KEYS`, `HS_SCRAPFLY_KEY_ROTATION_CREDITS`
- `SCRAPFLY_API_KEY` / `HS_SCRAPFLY_API_KEY` for a legacy single key

Provider keys and request URLs containing tokens must never be logged.
