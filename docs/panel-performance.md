# Производительность и навигация панели

База сравнения: `3246778` (редизайн от 7 сентября 2026). Изменения этого этапа
не требуют миграции базы, смены авторизации или перезапуска API.

## Что изменилось

- JavaScript подключается только для открытого раздела. Общая навигация,
  выбор колонок, темы, модальные окна и зависимости разделов сохранены.
- Статистика, парсеры, токены и редакторы больше не загружают невидимую
  страницу каталога с дополнительными данными карт.
- Семь счётчиков в боковой панели остаются актуальными. Медиа-покрытие
  рассчитывается только для открытого каталога; неиспользуемые запросы удалены.
  Кэширование и приблизительные итоги не вводились.
- Сортировка по названию и времени обновления применяется на сервере до
  пагинации. У каждого порядка есть уникальный завершающий ключ; для
  Standard/Wild внутренний и внешний порядок совпадают.
- Размер страницы доступен рядом с сортировкой. Переход по номеру сохраняет
  поиск, раздел, фильтры и порядок. Формы работают и без JavaScript.
- Автопоиск не отправляет повторный запрос из-за пробелов в неизменившейся
  строке и ждёт завершения составного ввода (IME). При отправке виден статус.
- Мобильная навигация переносится на следующую строку, не обрезая кнопки.

## Проверки

```sh
make check PYTHON=/path/to/validated/venv/bin/python
make security
make panel-browser-check
```

`make check` запускает тесты панели, в том числе бюджеты запросов и JS,
allowlist сортировки и SQL ordering на синтетических данных. Node 22 (как в
CI) использует SQLite только в памяти: проверяются существующие в MySQL-схеме
поля, порядок, LIMIT/OFFSET, равные названия, NULL и две стадии Standard/Wild.
Это не проверка колляции или плана MySQL. Рабочая база не используется.

Браузерный набор: 45 сценариев, 14 вариантов каталога, ширины 320/390/768/1024/1440,
вход и другие разделы на fixtures, сохранение фильтров, сортировка, переход,
fallback без JS, IME, просмотр изображений статистики и фактические запросы ресурсов. Fixtures используют тот
же manifest скриптов, что production. Скриншоты дополнительно проверяются
визуально; регрессия обрезания пагинации защищена отдельным DOM-утверждением.

Дополнительно проверены PHP 7.4 helper-тесты и синтаксис изменённых runtime-файлов.
Полный `make check` прошёл с существующими deprecation warnings; локальная
проверка C# SDK пропущена из-за отсутствия `dotnet`. `make security` — без находок.

## Просмотр данных и изображений

По умолчанию каталог открывается в режиме «Просмотр»: ограниченный по высоте
список записей и выбранная карточка рядом. На телефоне список заменяется
обычным селектором; есть кнопки предыдущей/следующей записи. Стрелки вверх/вниз
и Home/End работают внутри списка. Серверные фильтры и пагинация не меняются.

- Изображения и доступные медиа связанной записи собраны вместе, URL-дубликаты
  удалены. Галерея показывает шесть миниатюр на странице; все оставшиеся
  доступны через переключатель страниц. На телефоне миниатюры идут в три
  колонки с целями нажатия не меньше 44 px. Для единственного изображения
  повторная миниатюра и стрелки скрыты. Полный экран сохраняет фокус.
- Звуки и видео не запускаются автоматически; при переключении запись/медиа
  воспроизведение останавливается. Отсутствующее или недоступное изображение
  имеет явное состояние, не блокирующее другие данные.
- Основные характеристики видны сразу. Селектор «Данные записи» открывает
  любой исходный столбец/раздел данных, включая скрытые колонки, Wiki, связи и историю.
  Вложенные спойлеры превращены в обычные заголовки и текст, длинные разделы
  ограничены по высоте. Данные для подробностей создаются только для выбранной
  записи, без новых HTTP/SQL-запросов и без повторной серверной выборки.
- Режим «Таблица» сохраняет исходные формы, колонки, плотность и действия.
  Предпочтение режима хранится локально. В новый просмотр не копируются формы,
  CSRF-поля, ссылки действий, обработчики событий, HTML IDs или произвольная разметка; допустимы лишь
  текстовые элементы и HTTP(S)-ссылки. Без JS или при недоступном модуле работает
  исходный каталог.

Тесты используют реальные PHP-представления с синтетическими записями:
переходы по 15 изображениям, дедупликация, Buddy/Wiki/история изменений, аудио,
видео, отсутствие копий форм, безопасный текст/ссылки, названия связей из title,
подписи аудио, недоступные картинки и модуль, 120 записей в ограниченном списке,
возврат в таблицу и мобильная раскладка. Это проверка
отображённых исходным шаблоном полей, не обещание отображения дополнительных
полей базы или снятия существующих серверных ограничений выборки.

## Дополнение: один проход для счётчиков открытого каталога

Относительно `a5c43f9` запросы блока счётчиков сокращены: герои 12 → 7,
скины 11 → 8, питомцы 10 → 7, Standard/Wild 12 → 9. Навигационный итог и
покрытие одной таблицы вычисляются одним условным агрегатом. Точность,
предикаты статусов и JSON, COUNT DISTINCT семейств, rarity-группы и глобальные
связи первой монетки сохранены; кэша или миграций нет.

PHP recorder проверяет бюджеты; Node исполняет полученный SQL на изолированной
SQLite с узкой совместимостью MySQL JSON-функций. Проверены пустые таблицы,
SQL NULL / JSON null, отсутствующие ключи, пустые массивы/URL, частичные и
ошибочные записи, повторяющиеся семейства и исключённые форматы. Это проверка
результатов и числа запросов, не измерение времени/EXPLAIN рабочей MySQL.
Test-toolchain: Node 22 и PHP 8 CLI для SQL recorder внутри Node-теста.
PHP 7.4 проверяется отдельно: синтаксис runtime и PHP helper-тесты;
совместимость нового runtime с PHP 7.4 не требует PHP 8 на production.

## Дополнение: отзывчивость просмотрщика и компактная навигация

- На 120 синтетических записях десять переключений раньше вызывали 12 100
  повторных изменений `hidden` в исходной таблице. Теперь — 0 изменений и
  0 обходов её строк. Observer реагирует только на изменения целевой таблицы,
  сохраняя поддержку обновления строк парсеров и полной замены таблиц статистики.
- «Назад» и перезагрузка восстанавливают выбранный ID и поле в просмотрщике.
  В history текущей страницы сохраняются только ID и ключ поля, не данные
  записи; новая страница начинается с первой записи. Исчезнувший ID безопасно
  возвращает просмотр к первой записи. Тексты, SQL-результаты и изображения не кэшируются.
- При пагинации и отправке фильтров сразу видны статус загрузки и синяя полоса.
  Состояние сбрасывается при возвращении страницы из history и по таймауту.
  Переходы остаются обычными серверными ссылками/формами, без SPA и фоновой
  предзагрузки базы. Ускорение чтения обеспечивается сокращением запросов выше.
- Мобильная панель сортировки и размера страницы занимает одну строку.
  В тесте «Герои» шириной 390 px начало просмотрщика поднялось примерно с
  883 до 618 px. Длинные заголовки переносятся; элементы управления не обрезаются
  на 320 px. Переключатель записей закрепляется при прокрутке подробностей.
- JS: 5 запросов, 43 948 байт без сжатия; исходный бюджет 44 KB не повышался.
  Изменённым скриптам и CSS присвоены новые версии для следующей выкладки.

Регрессии проверяют отсутствие не только записей атрибутов, но и чтения
`table.rows` при переключениях, историю/перезагрузку, pending/pageshow,
мобильную компактность и доступность закреплённых контролов. До исправлений
тесты новых сценариев воспроизводили старые проблемы. Локальные screenshots
используют синтетическую графику, не рабочие данные.
Итоговый браузерный набор после дополнения: 49 сценариев; `make check` и
`make security` прошли. Локальный C# SDK gate по-прежнему не запускался из-за
отсутствия `dotnet`. Независимое Sol-ревью не выявило блокирующих замечаний;
замечания о проверке поля после reload и версии PHP test-toolchain учтены.

## Не входит в этот этап

Не менялись schema/indexes, данные, операции записи, OAuth/CSRF, парсеры,
расписания, API и deployment-конфигурация. Автоматическая публикация не выполняется.
Авторизованный production browser flow и время SQL на реальных объёмах не
измерялись. Поиск `%строка%` по тексту/JSON и семь навигационных COUNT остаются
потенциально дорогими на большой базе. Индексы, full-text или кэш требуют
отдельных EXPLAIN/замеров и решения о допустимой свежести и семантике поиска.
